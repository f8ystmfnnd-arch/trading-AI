# Development Rules

## 기본 원칙

이 프로젝트는 `BTC Market Regime & Risk Guard AI`이다. 가격 예측보다 리스크 관리가 우선이며, 방향성 예측은 보조 신호다.

개발 중에는 데이터 무결성, 시간 순서, 백테스트 신뢰성을 최우선으로 둔다.

## Lookahead Bias 방지

미래 정보를 현재 피처나 의사결정에 섞으면 안 된다.

- 현재 시점의 피처는 현재까지 확인 가능한 데이터만 사용한다.
- 타깃 생성 시 미래 수익률이나 미래 변동성은 label로만 사용한다.
- rolling feature는 미래 행을 참조하지 않는다.
- 리샘플 데이터는 candle close 이후에만 사용 가능한 것으로 간주한다.
- 뉴스 데이터는 실제 공개 시각 이후에만 사용할 수 있다.

## Time-Series Split

검증은 시간 순서를 지켜야 한다.

- train, validation, test는 시간 순서대로 나눈다.
- 과거 데이터로 학습하고 미래 데이터로 검증한다.
- `shuffle=True`는 기본적으로 사용하지 않는다.
- cross validation이 필요하면 time-series 전용 방식을 사용한다.
- walk-forward 검증을 우선 고려한다.

## 백테스트 원칙

- 수수료와 거래 횟수를 반드시 고려한다.
- buy and hold 대비 수익률만 보지 않는다.
- MDD 감소, 고변동 구간 회피, 급락 구간 회피를 함께 본다.
- 포지션 축소가 실제로 위험 감소에 기여했는지 확인한다.
- threshold 튜닝은 test 데이터에 과적합하지 않도록 분리한다.

## 데이터와 산출물 관리

대용량 데이터와 생성 산출물은 GitHub에 올리지 않는 방향으로 관리한다.

- `data/raw/` 파일을 임의로 삭제하지 않는다.
- `data/processed/` 파일을 덮어쓰기 전에 입력과 생성 조건을 확인한다.
- `model/` 또는 `models/`의 모델 파일을 함부로 삭제하지 않는다.
- `experiments/`의 대용량 결과 파일을 임의로 수정하지 않는다.
- 중요한 실험 결론은 작은 Markdown 요약으로 남긴다.

## Git 작업 원칙

- 사용자가 명시적으로 요청하지 않으면 `commit`하지 않는다.
- 사용자가 명시적으로 요청하지 않으면 `push`하지 않는다.
- 사용자가 명시적으로 요청하지 않으면 PR을 만들지 않는다.
- 작업 전후로 변경 파일 목록을 확인한다.
- 사용자 변경으로 보이는 파일은 되돌리지 않는다.

## 뉴스 데이터 사용 원칙

뉴스는 매수/매도 신호가 아니다.

- 긍정 뉴스면 매수, 부정 뉴스면 매도 같은 단순 로직을 사용하지 않는다.
- 뉴스는 변동성, 불확실성, 이벤트 위험도 판단에 사용한다.
- 뉴스 점수는 차트 기반 리스크 점수와 결합해 최종 risk score에 반영한다.
- 뉴스의 영향 시간대를 short / medium / long으로 구분한다.

## Mode 분리 원칙

`Day Trading Mode`와 `Swing Trading Mode`는 목적과 시간축이 다르므로 분리해서 설계한다.

- `Day Trading Mode`: 1m / 5m / 15m / 1h 중심, 신규 진입 위험과 단기 변동성 판단
- `Swing Trading Mode`: 15m / 1h / 4h / 1d 중심, 시장 국면과 포지션 유지 위험 판단

## 수집 기능 우선순위

`collect_bybit_1m.py`는 먼저 다음 기능을 안정화한다.

- `--days`
- `--update`

`--watch`는 실시간 대시보드 단계에서 다룬다.
